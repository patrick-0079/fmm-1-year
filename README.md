# 芙眠眠一周年 · 晚安小世界

暖木色、薰衣草紫、樱花粉、薄荷绿与溪水蓝搭配的像素风 H5 周年探索游戏。控制 Q 版芙芙，在晚安小屋、周年花园、勇气花园、晚安周年小镇四张地图间探索；全部逻辑在浏览器内运行，不需要后端、数据库或服务端函数。

## 开发和构建

需要 Node.js 22.12+（建议 Node.js 24）。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

开发服务器下可访问 `/tests/media-fixture.html` 检查四类媒体、长留言和素材缺失提示。测试音视频在浏览器内临时生成，测试内容不会进入正式内容配置或生产构建。

`/tests/mobile-fixture.html` 提供 375 与 320 像素宽度的真实页面框架，用于检查手机布局、方向键、陷阱和地图内复活提示；同样不包含在生产构建中。

生产产物在 `dist/`，可以部署到任意静态托管服务。它是一个单页网站及其本地资源文件，需通过 HTTP/HTTPS 访问，不能直接双击 HTML 使用 `file://` 打开。

## 已包含的玩法

- 室内：长按吹蜡烛 → 拖动切蛋糕 → 分享第一块蛋糕；四对礼物翻牌配对。
- 室外：给三只气球充气并放飞；点夜空释放烟花；向弹幕祈愿屏发射预设祝福；小电视打卡站。
- 电脑：WASD / 方向键移动，E / 空格互动，Esc 收起当前地图互动。
- 鼠标可独立游玩：左键点击地面寻路，点击物件或标记走近互动；右键也能走近并互动，在小游戏里执行主要动作。右键长按可吹蜡烛或蓄力跳跃，不弹出浏览器菜单。小游戏提供可点击的方向与动作按钮。
- 键盘可独立游玩：Tab 切换按钮，Enter / 空格确认；E 在当前互动中执行选项，长按 E 吹蜡烛，礼物配对可直接按数字 1–8。四个经典小游戏继续使用方向键 / WASD、空格，E 也可执行主要动作。
- 手机：虚拟方向键 + 互动按钮；也可以点击地面自动寻路、点击发光标记前往互动。
- 所有小游戏直接在地图里绘制和操作，蛋糕与礼物会拉近原场景镜头。烟花从实际烟花筒升空、气球从摊位飞走、预设弹幕在花园屏幕上飘过。信件与媒体在地图下方的只读阅读区展开；生产页面没有 dialog 或遮罩弹窗。
- 家具碰撞、自动寻路、室外镜头跟随、本机探索进度、原创浏览器合成 BGM 与音效、减少动态效果支持。音乐、音效分别开关，音量使用加减按钮。
- 四种陷阱集中在第三张「勇气花园」：绊脚缎带、苔藓石、迷雾、回旋风。小屋与周年花园没有陷阱；普通家具仍有碰撞。所有陷阱都固定让芙芙回到小屋的床上躺下，已完成的心愿与回忆保留，不再有户外复活点。
- 小屋的床可以主动躺下，长椅互动后会真正坐下。按 E、方向键、虚拟方向键或场景中的「起身」按钮离开休息姿势；起身回到床边或椅子前的安全位置。走到勇气花园终点可摘勇气之花，完成第五个心愿。
- 两座花园增加了树木和可以走近的小溪，溪水有流动纹理，木桥允许横穿；水面有独立碰撞。绊脚石、长椅、花环与休息姿势使用细化的像素素材，烟花提供心形、星形与金色花火，带升空尾迹和闪光细节。
- 可以摘苹果、采花、捡花环与星屑，采摘后物件会变化。按 **H** 或点击场景按钮快捷戴上/摘下花环，也可以按 **B** 或点击工具栏背包管理全部饰品。每天每棵树有三颗苹果、每片花丛可采三朵，下一游戏日刷新，累计数量保留。
- 小镇有错落的主街、分岔小巷、阶梯院落、心形小广场、池塘和溪边街道；花店、烘焙屋、工坊、邮局、相册书屋和晚安电台沿街分散。15 名原创虚构 NPC 可在地图内交谈，迎宾员可赠送周年胸针。
- 栅栏与水面有碰撞；树木、果实、NPC 与人物按脚底位置排序。夜间有蓝色环境光与暖色路灯、窗灯，烟花使用多组彩色粒子。

## 小镇小游戏与纪念背包

四个小游戏在街边摊位的屏幕中游玩，不打开弹窗。手账的游戏按钮会自动走到摊位；也能直接走近互动。

花园右下方有通往小镇的石路、路牌与牌楼。走近后按 E / 空格 / 右键，或点击入口，就会抵达小镇入口；从小镇入口的「周年花园」路牌可原路返回。所有地图的门都设置了对应出口，使用地图内通路切换时会在对面的门边落脚；底部导航仍可快速切换地图。

| 游戏         | 操作与通关条件                                            | 周年奖励       |
| ------------ | --------------------------------------------------------- | -------------- |
| 星糖贪吃蛇   | 方向键 / WASD，收集 6 颗星糖                              | 一周年星糖发夹 |
| 晚安方块     | 左右移动、上键旋转、下键加速、空格直接落下，累计消除 4 行 | 晚安星星耳机   |
| 月兔跳一跳   | 按住空格或地图按钮蓄力，松开跳跃，到达 8 个平台           | 月兔纪念背包   |
| 芙芙晚安飞行 | 反复轻按空格或地图按钮拍翅，穿过 8 道星门                 | 星翼发饰       |

手机使用摊位下方的方向与动作按钮。失败可立即重试，Esc 或「离开摊位」返回地图。通关奖励直接进入背包，每种只收一件，重复游玩不会堆叠。头饰与随身饰品各可装备一件，同一位置的饰品互相替换；点击「脱下」可卸除。饰品按人物朝向与坐姿对齐，背包区分身前背带与身后背包，耳机使用贴合头部的佩戴造型。**睡觉时全部饰品自动隐藏，起身后恢复原来的佩戴选择**，不会清空背包或装备记录。

`src/equipment.ts` 定义六种饰品的前后层与朝向，`src/avatar.ts` 统一绘制游戏人物；开发时可访问 `/tests/equipment-fixture.html` 一次检查全部饰品的四个朝向、坐姿与睡姿，验收页不修改存档，也不包含在生产构建中。

`src/town-data.ts` 配置 15 名居民的名字、职业、对话、位置，以及四个摊位的位置、说明和奖励；后续可扩充居民数组。`src/town-map.ts` 定义小镇地形、栅栏、建筑和交互点；`src/arcade-engines.ts` 是小游戏规则；`src/items.ts` 定义饰品与装备规则。背包保存在 `fufu-souvenirs-v1`，自动迁移旧版花环；居民认识记录保存在 `fufu-town-talked-v1`。重新探索会一起清空这些本机进度。

小镇的可走区域在 `src/town-surfaces.ts`，按道路、台阶、院落和游乐摊位铺地的实际范围定义；种植区、树丛、屋顶和水面不能穿行。键盘与自动寻路使用同一套脚底范围检查，接缝也会逐段验证。`src/town-scenery.ts` 定义树冠遮挡轮廓与周年装饰；树冠按树根位置排序，人物从后方经过时会被枝叶正确遮住。新增铺地复用原地图石板纹理，广场蛋糕复用现有像素素材。

入口周年拱门、广场庆典蛋糕、气球花束、彩旗灯串和六间店铺的周年限定横幅分布在街区中。小镇夜幕降低遮光强度、扩大路灯照亮范围，保持道路与人物可辨认。NPC 对话显示头像、姓名和职业，配色与像素木框保持一致；电脑端在地图下缘显示，窄屏在地图内操作区域接续显示。长椅坐姿期间隐藏该长椅的互动标记，避免遮住人物；勇气之花已使用具体花朵取代旧占位圆形。

吹蜡烛采用长按操作，不请求麦克风权限。首次进入点击「开始」后播放轻柔音乐与音效，已有静音偏好会保留。BGM 与音效由 Web Audio 在本地合成，没有外部音乐下载；真实录音和视频仍由访客主动播放，播放时背景音乐会降低音量。探索、背包、花冠与时钟只保存在当前浏览器，不会上传。

## 昼夜和限时彩蛋

现实 **600 秒 = 游戏一天**。初次打开从 08:00 开始，四张地图共享同一时钟，刷新和切地图不会重置时间。清晨 05:00–08:00、白昼 08:00–17:00、黄昏 17:00–20:00、星夜 20:00–次日 05:00；地图光照、室内窗景、灯光和水面随时段变化。

花园的长椅可以「歇到下一个时段」，无需一直等待。清晨出现晨露花，黄昏出现小纸船，夜间出现萤火心愿；限定物件及标记只在对应时段出现，每座花园每天各能收集一次。时间规则在 `src/day.ts`，场景变化、采摘和本机背包在 `src/nature.ts`。

夜色保留较明亮的地图底色、暖色灯光和月夜变化。烟花绽放时会在夜空中浮现周年祝福，逐渐升起、淡出；预设文字在 `src/celebration.ts` 的 `fireworkWishes` 中维护，不需要访客输入或后端。

页面不提供文字输入、留言提交、文件上传或录制功能。信件与媒体是维护者写入项目的只读内容；弹幕屏只播放按钮选择的预设祝福，不会发送到 B 站或任何服务器。

## 添加留言、图片、音频和视频

已接入 `ref/素材/Kerry/留言.txt` 的真实祝福，图片、音频、视频仍展示占位界面。将媒体放入 `public/media/`，在 `src/content.ts` 的对应 `items` 中填入内容，然后重新构建。侧栏会自动显示内容数量。

```ts
// collections.letters.items：文字留言
{ id: 'letter-01', title: '一周年快乐', author: '署名', text: '在这里写完整留言。\n支持换行。' }

// collections.album.items：图片，建议 WebP / PNG / JPG
{ id: 'photo-01', title: '想珍藏的瞬间', src: '/media/photo.webp', alt: '图片说明', text: '可选配文' }

// collections.radio.items：音频，建议 MP3
{ id: 'audio-01', title: '一封声音来信', author: '署名', src: '/media/good-night.mp3', text: '可选配文' }

// collections.tv.items：视频，建议 H.264 + AAC 编码的 MP4
{ id: 'video-01', title: '周年纪念片段', src: '/media/anniversary.mp4', text: '可选配文' }
```

每个物件可以配置多条内容。素材缺少、加载失败、列表为空均有提示；切换或关闭播放器时停止原来的媒体。媒体地址是实际文件路径，不是 B 站视频页面链接。

`src/content.ts` 还包含首播日、周年日和 B 站主页链接。`src/maps.ts` 定义地图、碰撞与互动点；`src/world.ts` 实现移动和场景绘制；`src/activities.ts` 实现周年小游戏。

## 陷阱、复活点与鼓励文案

`src/maps.ts` 与 `src/town-map.ts` 定义四张地图的可行走边界、家具、树干、水面、互动位置与陷阱。`src/landscape.ts` 的溪水形状同时用于绘制与碰撞。碰撞以脚下的小圆形区域计算。角色图集不是严格对齐的网格，`src/sprite-frames.ts` 使用各姿势的实际裁切范围、统一缩放与脚底基线；坐姿和睡姿也使用真实轮廓裁切。点击发光标记时，自动寻路会绕开家具、水面和陷阱；点击陷阱本身可以体验一次复活。

唯一复活点和起身位置在 `src/rest.ts` 的 `HOME_BED` 中。首次复活会展开地图里的床边便签，文字为「小叶子让你休息一下再重新出发，辛苦啦宝宝」，完整配上用户提供的四格插画。原图保存在 `src/assets/xiaoye-note.png`，网页使用优化后的 WebP；样式与内容在 `src/bed-note.ts`、`src/world-details.css`。便签不阻塞游戏，没有弹窗遮罩。

首次展开状态保存在当前浏览器，后续复活不会重复自动展开；可以在床边点击「床边便签」重看，或通过床的互动菜单打开。重新探索会重置首次便签状态。

后续复活可以轮换显示 `src/content.ts` 的 `encouragements`，不填写时保留简短的回床休息提示：

```ts
{ title: '可选标题', message: '在这里填写鼓励的话。', author: '可选署名' }
```

开发时访问 `/?debug=collision` 可以显示家具轮廓、可行走边界、脚下碰撞区域、路径和坐标，便于核对地图。该调试视图只在开发环境启用。

## 向 main 推送后自动构建发布

使用 Cloudflare 自带的 Git 构建，不需要额外写 GitHub Actions，也不需要把令牌放入仓库：

1. 在 Cloudflare 的 **Workers & Pages** 里打开 `fmm-1-year`。
2. 在 **Settings → Build** 连接 GitHub 仓库 `patrick-0079/fmm-1-year`。已有连接时确认仍然启用。
3. 在 **Settings → Build → Branch control** 把生产分支设为 **`main`**。
4. 构建命令填写 **`npm run build`**，部署命令填写 **`npx wrangler deploy`**，根目录为仓库根目录，构建变量 `NODE_VERSION=24`，然后保存。
5. 后续推送到远端 `main`，或把 Pull Request 合并进 `main`，都会自动运行构建与部署。可以在 Cloudflare 的 Builds 中查看对应提交的日志和发布结果。

例如修改本项目后执行：

```sh
git switch main
git add src README.md
git commit -m "Update anniversary adventure"
git push origin main
```

触发条件是远端 `main` 收到新的推送；只在本地 `git commit` 尚未推送时，Cloudflare 不会收到事件。预览构建用于其他分支，不是生产自动发布的开关。

如果没有自动发布，优先检查 GitHub 应用是否授权此仓库、Git 构建连接是否启用、生产分支是否确实为 `main`，以及 Cloudflare 的构建日志。若项目最初通过直接上传创建，需要先建立 Git 构建连接。

以上行为依据 [Cloudflare GitHub integration](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/github-integration/) 与 [Build branches](https://developers.cloudflare.com/workers/ci-cd/builds/build-branches/)。

## Cloudflare 部署

以下两种方式都部署纯静态网页。选择一种即可；游戏没有后端处理逻辑。

### Workers Git 构建界面（有“创建新令牌”的界面）

仓库中已加入 `wrangler.jsonc`，将 `dist/` 作为静态资源目录，不配置服务端入口、数据库或存储绑定。

| 配置项                       | 填写方式                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------- |
| 项目名称                     | `fmm-1-year`（如自行改名，同时修改 `wrangler.jsonc` 的 `name`）                                   |
| 仓库                         | `patrick-0079/fmm-1-year`                                                                         |
| 生产分支                     | `main`                                                                                            |
| 构建命令（可选）             | `npm run build`。虽然界面标注可选，本项目需要构建，必须填写。                                     |
| 部署命令                     | `npx wrangler deploy`                                                                             |
| 启用预览构建                 | 开启；非生产分支用于预览。                                                                        |
| 预览命令（如显示）           | 保留默认 `npx wrangler preview`。                                                                 |
| 使用 Cloudflare Access 保护  | 面向粉丝公开访问时关闭。开启会要求受保护地址的访客登录。若开关注明仅保护预览，则只影响预览地址。  |
| 高级设置 → 根目录            | `/`，即仓库根目录。                                                                               |
| 高级设置 → API 令牌          | 保留“创建新令牌 / 将自动创建新令牌”，由 Cloudflare 自动管理部署凭据；不需要在网页代码里填写令牌。 |
| 构建变量名称                 | `NODE_VERSION`                                                                                    |
| 构建变量值                   | `24`                                                                                              |
| 其他变量、Secrets 与存储绑定 | 留空。                                                                                            |

本地可执行 `npx wrangler deploy --dry-run` 验证静态部署配置；实际部署仍由你在 Cloudflare 中完成。

### Pages Git 构建界面（有“构建输出目录”的界面）

连接 GitHub 仓库 `patrick-0079/fmm-1-year`，填写：

| 配置      | 值                         |
| --------- | -------------------------- |
| 生产分支  | `main`                     |
| 框架预设  | None                       |
| 构建命令  | `npm run build`            |
| 输出目录  | `dist`                     |
| 根目录    | 留空（仓库根目录）         |
| Node 版本 | 环境变量 `NODE_VERSION=24` |

如显示预览构建则开启；公开纪念站的 Access 保护关闭。Pages 的预览 Access 开关仅保护预览部署，默认不会保护正式 `pages.dev` 或自定义域名。

也可以把本地构建的 `dist` 目录直接上传到 Pages。Pages 这条路径无需部署命令、Functions 或手动设置 API 令牌。

官方配置依据：[Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)、[Workers 静态资源](https://developers.cloudflare.com/workers/static-assets/get-started/)、[Pages 构建配置](https://developers.cloudflare.com/pages/configuration/build-configuration/)、[Pages 预览访问控制](https://developers.cloudflare.com/pages/configuration/preview-deployments/)。

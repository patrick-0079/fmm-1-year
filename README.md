# 芙眠眠一周年 · 晚安小世界

暖木色、薰衣草紫、樱花粉、薄荷绿与溪水蓝搭配的像素风 H5 周年探索游戏。控制 Q 版芙芙，在晚安小屋、周年花园、勇气花园、晚安周年小镇和回声遗迹五张常规地图间探索，集齐七色花后可进入彩蛋地图「花海」。全部逻辑在浏览器内运行，不需要后端、数据库或服务端函数。

## 沿途的居民

小镇的 15 位居民各有自己的对白。去邮局找红笺，收件后在小屋或网页的「晚安信箱」里拆信。花店的青芽会送一束能在背包「纪念物」里翻看的洋桔梗，栗栗会举起白板，把第一块草莓蛋糕留给你。银铃需要叫两次才会抬头。走远可以自然结束交谈，回头再聊也能试试其他回答。

勇气花园南门内、石路左边住着园丁爷爷。回声遗迹南阶上方的守护者会在你答应试试谜题后赠送《遗迹手记》。已经点亮星纹砖的玩家也可以找她领书，听她送上祝福。

## 开发和构建

需要 Node.js 22.12+（建议 Node.js 24）。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

日常修改后可运行 `npm run check`，依次执行全部单元/地图回归测试、TypeScript 检查和生产构建。默认开发地址为 `http://127.0.0.1:5173/`，生产预览为 `http://127.0.0.1:4173/`；端口被占用时以终端输出为准。

开发服务器下可访问 `/tests/media-fixture.html` 检查四类媒体、长留言和素材缺失提示。测试音视频在浏览器内临时生成，测试内容不会进入正式内容配置或生产构建。

`/tests/mobile-fixture.html` 提供 375 与 320 像素宽度的真实页面框架，用于检查手机布局、方向键、陷阱和地图内复活提示；同样不包含在生产构建中。

`/tests/interaction-fixture.html` 对真实控制器执行背包暂停、焦点、组合键、礼盒延迟及后台恢复检查，不写入存档。其他验收页、发布前检查和配置文件位置见 [维护手册](MAINTENANCE.md)。

生产产物在 `dist/`，可以部署到任意静态托管服务。它是一个单页网站及其本地资源文件，需通过 HTTP/HTTPS 访问，不能直接双击 HTML 使用 `file://` 打开。

## 本机存档与贴图缓存

开始探索后，手账会显示「本机已保存」和地图名。移动时约每两秒记录一次位置；切换地图、坐下、躺下、离开页面或切到后台也会保存。可以随时点手账里的「保存进度」。下次用同一浏览器打开同一网址，点「继续上次的冒险」即可回到原处。休息时离开会从床边、长椅前或营火旁起身；旧位置变为障碍时，会回到该地图的安全入口。

收藏、已完成的心愿、七色花、落星、正式获得的饰品与搭配、认识的居民、遗迹的碑文与电波、星盘环、缺口和铜镜的朝向和七个小游戏的最高分都会保留。单局小游戏棋盘不续局。旧版存档会继续保留已获得的内容；第一次使用位置存档前从小屋开始。「重新探索」会清空游玩进度，保留音量设置和已下载素材。存档留在当前浏览器，清除站点数据会同时清除它和资源缓存。

正式构建会在浏览器首次用到地图、角色或道具贴图时缓存它。刷新后直接复用；美术更新会产生新的文件名，只需下载改变的贴图。首次打开会优先下载小屋和人物。其余地图的底图在首次进入时加载，转场会显示目的地，素材就绪后才开始行走。小镇高清图会在入镇后单独准备。要在本地验证贴图缓存请用 `npm run build` 和 `npm run preview`；正式站使用 HTTPS，开发服务器保留热更新行为。

## 已包含的玩法

- 小屋的窗边、床左侧有一把白色四弦贝斯。点琴身或靠近按 E / 空格 / 右键打开窗边乐谱，为芙芙跟弹原创周年曲《把晚安弹给你》。琴谱在小屋原有的 3:2 画面内展开，手机上的四根弦并排排列。可以先「听示范」，再点亮起的弦（手机可轻触），或用 **1 / 2 / 3 / 4** 拨 **E / A / D / G**。四句共 16 个音，不限时，弹错可重试。弹完会在本机记下这份演奏；之后可以自由拨弦、再弹一次，或按 Esc 收起琴谱。示范按同一张谱播放，只跟随提示弹完才会记录赠曲。琴声独立于背景音乐和脚步等音效。可在琴谱里开关琴声；总音量为零时点「恢复总音量」会恢复到 45%。
- 使用鼠标时，网页和地图使用芙芙的粉发爱心指针；指向可互动的地图物件、琴弦、按钮或链接时，箭头变成爱心拨片。触屏仍直接点按。
- 室内：长按吹蜡烛，依次沿三条虚线拖动切成六份，点小盘子观看芙芙吃蛋糕的过场；也可用键盘辅助切割。礼物配对使用精细礼盒、翻转动画与周年托盘，完成可获得缎带鞋。
- 室外：给三只气球充气并放飞；点夜空释放烟花与周年祝福；小电视打卡、CDN 周年放映。
- 电脑：WASD / 方向键移动，E / 空格互动，Esc 收起当前地图互动。
- 鼠标可独立游玩。左键点击地面寻路，点击物件或标记走近互动。右键与地图物件互动，长按可吹蜡烛或蓄力跳跃。在扫雷棋盘上，左键翻砖，右键在指针下的砖上插旗或拔旗。
- 键盘可独立游玩。Tab 切换按钮，Enter / 空格确认。E 在当前互动中执行选项，长按 E 吹蜡烛，礼物配对可按数字 1–8。小游戏使用方向键 / WASD、空格。扫雷时用方向键选砖，按菜单键插旗或拔旗，也可用 Tab 选中「标记所选格」再按 Enter。
- 手机：虚拟方向键 + 互动按钮；也可以点击地面自动寻路、点击发光标记前往互动。
- 所有小游戏直接在地图里绘制和操作，蛋糕与礼物会拉近原场景镜头。烟花从实际烟花筒升空、气球从摊位飞走、视频在花园大屏播放。信件与媒体在地图下方的只读阅读区展开；生产页面没有 dialog 或遮罩弹窗。
- 家具碰撞、自动寻路、室外镜头跟随、本机探索进度、原创浏览器合成 BGM 与音效、减少动态效果支持。音乐、音效分别开关，音量使用加减按钮。
- 四种陷阱集中在第三张「勇气花园」：绊脚缎带、苔藓石、迷雾、回旋风。小屋与周年花园没有陷阱；普通家具仍有碰撞。所有陷阱都固定让芙芙回到小屋的床上躺下，已完成的心愿与回忆保留，不再有户外复活点。
- 小屋的床可以主动躺下，长椅互动后会真正坐下。按 E、方向键、虚拟方向键或场景中的「起身」按钮离开休息姿势；起身回到床边或椅子前的安全位置。走到勇气花园终点可摘勇气之花，完成第五个心愿。
- 两座花园增加了树木和可以走近的小溪，溪水有流动纹理，木桥允许横穿；水面有独立碰撞。绊脚石、长椅、花环与休息姿势使用细化的像素素材，烟花提供心形、星形与金色花火，带升空尾迹和闪光细节。
- 可以摘苹果、采花、捡花环与星屑，采摘后物件会变化。按 **H** 或点击场景按钮快捷戴上/摘下花环，也可以按 **B** 或点地图左侧的草莓背包整理饰品。每天每棵树有三颗苹果、每片花丛可采三朵，下一游戏日刷新，累计数量保留。
- 小镇有错落的主街、分岔小巷、阶梯院落、心形小广场、池塘和溪边街道；花店、烘焙屋、工坊、邮局、相册书屋和晚安电台沿街分散。15 名原创虚构 NPC 可在地图内交谈，迎宾员可赠送周年胸针。
- 晚安小屋里有只可以摸摸的小狐狸。点它，或走近按 E、右键、轻触互动键，就能和它打个招呼。
- 周年花园里，气球客星星带来了奶油猫桃桃。先摸摸它，再决定是否一起旅行。霉霉准备好了庆典，第二次找她可以邀请垂耳兔棉棉。篮子旁的晴糖有些害羞，等她亲手递出一块蛋糕吧。对话可随时收起，也可以回来重看。
- 桃桃跟随时会转身、交替迈爪，追上芙芙后停步。与花园来宾和小镇居民对话时，走远会自动收起对白，按住的方向键和点击地面的寻路都会继续。
- 栅栏与水面有碰撞；树木、果实、NPC 与人物按脚底位置排序。夜间有蓝色环境光与暖色路灯、窗灯，烟花使用多组彩色粒子。

## 小镇小游戏与纪念背包

**回声遗迹**的入口在周年小镇右上角的废弃山洞。从广场沿东北石街走到旧矿场，经过矿车，沿两盏矿灯间的旧轨道向北走进洞口。也可以点击洞口、靠近按 E 或右键进入。遗迹南阶通回洞前空地，地图导航也能直达。

西廊蛇纹苔庭、北廊星图室、东廊琥珀矿井各保存一道铭文。触碰石座时就会抄下线索，可立刻返回探索。读齐三道铭文后，在中央祭坛翻阅拓本并尝试敲响符号。敲错会保留已经奏对的音，完整旋律会唤醒南阶旁的一处周年彩蛋。进度保存在本机，静音时可全程通过文字和石灯解谜。

编辑地图或替换壁画时参考[遗迹素材说明](ARTWORK-v22.md)。

**支线「替芙芙点亮星盘」**约需 5–8 分钟。南阶石台提示三枚遗物的方位，守护者赠送的手记可以带去其他地图。按 **B → 纪念物 → 遗迹手记** 阅读，点书签或用左右方向键翻页。去西廊、北廊和东廊拾起藤纹内环、星纹中环和黄铜外环，再到中央祭坛西侧装入星盘。读盘沿的提示，让三道缺口对齐，沿光纹转动两面铜镜，使月光落到星纹砖上。完成时「晚安回声胸针」会自动入袋，可自行佩戴。原来的祭坛与隐藏电波仍可单独探索。

手记共有五枚印章，分别记录初次拾环、集齐三环、修复星盘、引光成功和听到旧电波。离开、刷新或关闭网页后，同一浏览器会记住每一格机关朝向，听过电波的旧存档也能直接看到对应印章。

四个摊位留在周年小镇，另有三款游戏在回声遗迹的石室中。点手账里的游戏名会自动前往对应地图和玩法。进入小游戏时，棋盘在原有的 3:2 地图画面中央展开，人物与街景保持探索时的大小。开始、暂停、方向按钮和玩法说明都在画面下方。

周年花园有两条入镇的路。爱心广场南边的弯石径穿过白色矮栅门，通往小镇南街；东北角沿溪的小路接上木桥，通往小镇北街的石阶。向外走过门槛或桥面会自动换图，也可以点击木路牌、直接点入口，或走近按 E / 空格 / 右键。两条路都可原路返回，庭院中央原有的花拱门仍通往勇气花园。

**扫雷怎么看数字？** 数字表示周围最多八块砖（含斜角）中的裂隙数量，空白会自动展开相连的安全区域。首翻的砖和它的邻格都安全。插旗只是做记号，带旗的砖要先拔旗才能翻开。翻到裂隙则本局结束，翻开全部安全砖即过关，无需给所有裂隙插旗。手机直接点砖翻开，用「触屏插旗」切换为插旗或拔旗。每盘有三次安全提示，可自动翻开未标记的安全砖。

手机使用摊位下方的方向与动作按钮。失败可立即重试，Esc 或「离开摊位」返回地图。达标时领取奖励后，可选择「继续游玩」保留分数继续挑战；跳一跳持续生成平台，连连看和扫雷换新盘，矿工补充新一层星矿。任意游戏达到双倍目标，可额外获得花环兔斜挎包。飞行中的星星触碰后立即消失，不会重复拾取。奖励直接进入背包，每种只收一件，重复游玩不会堆叠。

**暂停与恢复：**小游戏中按 **P** 或点「暂停休息」可停下，按 P / E / 空格或点「继续挑战」恢复。切到其他窗口/标签页会自动暂停小游戏，回到页面后等待主动继续。在地图探索时，打开背包仍可用键盘、鼠标和触屏控制人物。小游戏中查看衣橱或说明会暂停本局，收起后继续；若本来已经手动暂停，则仍保持暂停。昼夜时钟继续按现实时间流逝。Ctrl / Command / Alt 组合键保留给浏览器，不会触发游戏动作。

点地图左侧的草莓背包或按 **B** 打开衣橱。「全部」陈列 15 件配饰，也可以单选头饰、衣服、鞋子、背包、胸针或同行伙伴，比较同一部位的搭配。电脑用物品格上方的部位标签筛选，手机点部位按钮选分类，用箭头翻页，在「身上」页查看当前穿搭。「纪念物」收着青芽的洋桔梗和守护者赠送的《遗迹手记》。

点一件已获得的配饰，粉框标出选择，左侧芙芙会试穿。选背包时芙芙会侧身，用镜子下方的箭头可以再转一圈。点「佩戴」确认，绿勾随即移到新搭配上。再点「脱下」可取下，伙伴的按钮为「同行」和「休息」。面板保持打开，可以接着换装。按 **B**、**Esc** 或点 **×** 收起，尚未确认的试穿会取消。键盘可用 **Tab / Shift+Tab** 选格、**Enter** 试穿和确认。正常模式下，确认的搭配保存在本机。睡觉时饰品与伙伴暂时隐藏，起身后恢复。

`src/equipment.ts` 定义佩戴素材的前后层与朝向，`src/avatar.ts` 统一绘制游戏人物；开发时可访问 `/tests/equipment-fixture.html` 一次检查全部纪念品的四个朝向、坐姿与睡姿，验收页不修改存档，也不包含在生产构建中。`src/garden-guests.ts` 配置庭院来宾，`src/garden-life.ts` 处理对话与宠物寻路。

### 试穿与正式上线

## 七色花谱与花海

周年庭院有两朵特殊花，勇气花园有两朵，周年小镇有三朵。橙色花是金盏菊，已有的橙色收集记录会自动迁移。勇气花园的勇气之花是一簇白雏菊。七色花很小，花瓣会偶尔闪一下；花上没有悬浮叹号。测试时在「调试 → 七色花与花海 → 七色花谱」查看线索和真实进度。走近按 E 或右键，也可直接点击花朵，采集范围保持不变。

收齐七种后，周年庭院西侧、气球摊南边会出现七色花门，地图导航也会显示「花海」。这里一直是月夜。穿过草地上的野花，可以看到吃草的羊和萤火虫，也可以坐到营火边休息。西边有一圈泛着薄荷色微光的月石：走到月芽传送阵中央、点击阵纹，或走近后按互动键，都能回到庭院的七色花门。

## 昼夜和限时彩蛋

现实 **600 秒 = 游戏一天**。初次打开从 08:00 开始。小屋、两座花园和小镇共享昼夜变化。花海保持月夜，遗迹由长明灯照明，在两处停留时外界时钟继续走。清晨为 05:00–08:00，白昼为 08:00–17:00，黄昏为 17:00–20:00，星夜为 20:00–次日 05:00。刷新和切地图都会保留时间进度。

花园的长椅可以「歇到下一个时段」，无需一直等待。清晨出现晨露花，黄昏出现小纸船，夜间出现萤火心愿；限定物件及标记只在对应时段出现，每座花园每天各能收集一次。时间规则在 `src/day.ts`，场景变化、采摘和本机背包在 `src/nature.ts`。

夜色保留较明亮的地图底色、暖色灯光和月夜变化。烟花绽放时会在夜空中浮现周年祝福，逐渐升起、淡出；预设文字在 `src/celebration.ts` 的 `fireworkWishes` 中维护，不需要访客输入或后端。

页面不提供文字输入、留言提交、文件上传或录制功能。信件与媒体是维护者写入项目的只读内容。手账里的「晚安信箱」可直接在页面阅读；走近小屋信箱互动，会在游戏内展开信纸，两种阅读位置可以互相切换。正文使用普通清晰字体，支持滚动、选中和键盘阅读。

文字与像素素材分开处理：界面使用微软雅黑 / 苹方等系统字体，游戏画布按实际显示尺寸与设备像素密度渲染；位图素材仍保留像素边缘，文字不再随低分辨率画布一起放大。问号按钮内提供完整说明，底部常驻提示包含鼠标、B 背包、H 花环操作。

## 添加留言、图片、音频和视频

已接入 `ref/素材/Kerry/留言.txt` 的真实祝福；花园小电视已接入 CDN 视频，小屋的相册、电台和放映室仍等待素材。将这些收藏媒体放入 `public/media/`，在 `src/content.ts` 的对应 `items` 中填入内容，然后重新构建。侧栏会自动显示内容数量。

```ts
// collections.letters.items：文字留言
{ id: 'letter-01', title: '一周年快乐', author: '署名', text: '在这里写完整留言。\n支持换行。' }

// collections.album.items：图片，建议 WebP / PNG / JPG
{ id: 'photo-01', title: '想珍藏的瞬间', src: '/media/photo.webp', alt: '图片说明', text: '可选配文' }

// collections.radio.items：音频，建议 MP3
{ id: 'audio-01', title: '一封声音来信', author: '署名', src: '/media/good-night.mp3', text: '可选配文' }

// collections.tv.items：视频，建议 H.264 + AAC 编码的 MP4
{ id: 'video-01', title: '周年纪念片段', src: '/media/anniversary.mp4', text: '可选配文' }
```

每个物件可以配置多条内容。素材缺少、加载失败、列表为空均有提示；切换或关闭播放器时停止原来的媒体。媒体地址是实际文件路径，不是 B 站视频页面链接。

`src/content.ts` 还包含首播日、周年日和 B 站主页链接。`src/maps.ts` 定义地图、碰撞与互动点；`src/world.ts` 实现移动和场景绘制；`src/activities.ts` 实现周年小游戏。

### 花园小电视：CDN 周年放映

花园的大屏幕可直接观看视频，也可以点击手账里的「花园小电视 · 周年放映」自动走过去。视频画面显示在地图的电视里，控制条沿用像素木框；已取消发送弹幕功能，观看时不会因切到祝福互动而中断。

`src/cinema-config.ts` 的 `gardenFilm.src` 配置 CDN 视频地址，`title` 配置片名。当前使用提供的占位 MP4；替换地址后重新构建即可，视频不会打包进 `dist`，Cloudflare 只托管网页静态文件，无需后端或令牌。

- **打开页面即异步准备影片**，不必先进入游戏或点击电视。首次完整下载时显示已接收的字节数与百分比，推荐 H.264 + AAC MP4。后续打开只向 CDN 请求版本信息（HEAD）：优先比对 `ETag`，读不到时同时比对 `Last-Modified` 和 `Content-Length`。版本一致就播放本机完整副本，不重新传输视频正文。
- 准备和缓冲时，电视屏幕与控制条显示 **LOADING** 提示。可以点击「离开，先去逛逛」或按 Esc，继续走动、切地图，稍后回来观看。失败时会显示「重新加载」按钮。
- 连续 **60 秒没有收到任何数据** 会取消卡住的请求并显示重试；每收到一段有效数据都会延长等待，不限制整段视频的总下载时长。重试会从头下载完整文件。HTTP 206 分段响应、空文件和长度不完整的文件不会误判为预载完成。
- 文件完整接收并校验后才写入浏览器的 Cache Storage；播放期间不再向 CDN 分段取流。当前占位片约 67.1 MiB。同地址换片或不能可靠辨别版本时重新下载，新片完整前保留旧副本；已有完整副本但暂时连不上 CDN 时，会提示正在使用上次缓存。浏览器拒绝持久缓存时，仍可播放本次下载的影片。
- 离开电视或切到后台会暂停播放，正在进行的下载仍可继续。回到当前页面可从暂停处接着看，刷新后播放时间从头开始。视频不写入游戏存档，也不进入静态部署包。
- 鼠标按钮、E / 空格 / 右键均可播放暂停，左右方向键可跳转 10 秒，**F 或「全屏观看」进入全屏**，Esc 返回地图内观看。全屏提供浏览器原生控制条、「返回地图内观看」和「离开放映」；不支持原生全屏时使用全窗口播放器。控制条也提供快进、后退、重播和静音，播放时 BGM 自动降低音量。

完整预载需要 CDN 允许 CORS 读取。公开纪念站可在 R2 桶的 Settings → CORS Policy 填入以下配置；使用自定义域名时，修改后清除视频 URL 的旧 CDN 缓存。配置依据：[Cloudflare R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)。

```json
[
  {
    "AllowedOrigins": ["*"],
    "AllowedMethods": ["GET", "HEAD"],
    "AllowedHeaders": ["Range"],
    "ExposeHeaders": ["ETag", "Last-Modified", "Content-Length", "Content-Range", "Accept-Ranges", "Content-Encoding"],
    "MaxAgeSeconds": 86400
  }
]
```

开发时可用带 `Origin` 请求头的 HEAD 请求检查响应是否包含 `Access-Control-Allow-Origin`。当前占位片也支持用修改时间和长度校验；显式暴露 `ETag` 可区分同一秒内替换的同大小文件。只允许 `http://localhost:3000` 无法覆盖本项目的 5173 / 4173 本地预览和 Cloudflare 正式域名。此配置仅允许读取，不开放上传接口。

## 陷阱、复活点与鼓励文案

`src/maps.ts`、`src/town-map.ts`、`src/ruins-map.ts` 和 `src/meadow-map.ts` 定义六张地图的可行走边界、家具、树干、水面、互动位置与陷阱。`src/landscape.ts` 的溪水形状同时用于绘制与碰撞。碰撞以脚下的小圆形区域计算。角色图集不是严格对齐的网格，`src/sprite-frames.ts` 使用各姿势的实际裁切范围、统一缩放与脚底基线；坐姿和睡姿也使用真实轮廓裁切。点击发光标记时，自动寻路会绕开家具、水面和陷阱；点击陷阱本身可以体验一次复活。

唯一复活点和起身位置在 `src/rest.ts` 的 `HOME_BED` 中。每次触发陷阱回床时，都会自动展开地图里的床边便签，文字为「小叶子让你休息一下再重新出发，辛苦啦宝宝」，完整配上用户提供的四格插画。原图保存在 `src/assets/xiaoye-note.png`，网页使用优化后的 WebP；样式与内容在 `src/bed-note.ts`、`src/world-details.css`。便签不阻塞游戏，没有弹窗遮罩。

第一次复活后，床边会保留便签图钉，平时也可重读。下一次触发任意陷阱时，便签会重新自动展开。

维护者可以在 `src/content.ts` 的 `encouragements` 添加鼓励语。第二次及以后的复活会把轮换文字附在原便签下方。

```ts
{ title: '可选标题', message: '在这里填写鼓励的话。', author: '可选署名' }
```

开发时访问 `/?debug=collision` 可以显示家具轮廓、可行走边界、脚下碰撞区域、路径和坐标，便于核对地图。这一 URL 开关只在开发服务生效；启用了调试台的静态构建也可在右下角开关碰撞轮廓。

## 向 main 推送后自动构建发布

使用 Cloudflare 自带的 Git 构建，不需要额外写 GitHub Actions，也不需要把令牌放入仓库：

1. 在 Cloudflare 的 **Workers & Pages** 里打开 `fmm-1-year`。
2. 在 **Settings → Build** 连接 GitHub 仓库 `patrick-0079/fmm-1-year`。已有连接时确认仍然启用。
3. 在 **Settings → Build → Branch control** 把生产分支设为 **`main`**。
4. 构建命令填写 **`npm run build`**，部署命令填写 **`npx wrangler deploy`**，根目录为仓库根目录，构建变量 `NODE_VERSION=24`，然后保存。
5. 后续推送到远端 `main`，或把 Pull Request 合并进 `main`，都会自动运行构建与部署。可以在 Cloudflare 的 Builds 中查看对应提交的日志和发布结果。

例如修改本项目后执行：

```sh
git switch main
git add src README.md
git commit -m "Update anniversary adventure"
git push origin main
```

触发条件是远端 `main` 收到新的推送；只在本地 `git commit` 尚未推送时，Cloudflare 不会收到事件。预览构建用于其他分支，不是生产自动发布的开关。

如果没有自动发布，优先检查 GitHub 应用是否授权此仓库、Git 构建连接是否启用、生产分支是否确实为 `main`，以及 Cloudflare 的构建日志。若项目最初通过直接上传创建，需要先建立 Git 构建连接。

以上行为依据 [Cloudflare GitHub integration](https://developers.cloudflare.com/workers/ci-cd/builds/git-integration/github-integration/) 与 [Build branches](https://developers.cloudflare.com/workers/ci-cd/builds/build-branches/)。
